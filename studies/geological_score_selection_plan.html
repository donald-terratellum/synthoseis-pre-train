Geological Score Selection Study Plan

Plan for selecting 500 ordered examples from any discovered seismic zarr dataset under /Users/donaldpg/synthoseis/fake_data.

Goal

Create a study that uses geological_score to bias selection toward more complex and interesting geologic patterns while preserving spatial diversity across the full zarr volume.

  • Target example size: 128x128x128
  • Boundary margin: 64 voxels on every axis
  • Candidate pool: 1000 3D points per dataset
  • Final selection: 500 accepted points when possible

Phases

Phase 1: Requirements lock and dataset discovery

  1. Confirm the exact zarr key name is geological_score.
  2. Define dataset discovery under the fake-data root.
  3. Confirm axis order and score access semantics.
  4. Enforce the 64-voxel interior margin.

Review gate: verify the study can discover datasets and read the score key without loading full volumes unnecessarily.

Phase 2: Candidate generation and score ranking

  1. Generate 1000 interior candidates using a fast 3D spacing method inspired by Mitchell’s best candidate or Poisson-disc sampling.
  2. Keep all candidates inside the allowed interior region.
  3. Read geological_score at each candidate.
  4. Sort candidates from highest score to lowest score.
  5. Run a sensitivity test across multiple discovered datasets and average the acceptance success rate for each candidate-count setting so the default can be increased if 1000 does not reliably produce 500 accepted outputs.

Review gate: verify the sampler is reproducible, the ranking happens before greedy acceptance, and the sensitivity test justifies the final default starting-point count.

Phase 3: Greedy selection with adaptive spacing

  1. Accept the highest-scoring candidate first.
  2. Compare each remaining candidate to the previous 3 accepted points, or all accepted points if fewer than 3 exist.
  3. Accept a point only if it is farther than dist_thresh from all of the previous 3 accepted points, or from all accepted points if fewer than 3 exist.
  4. Reduce dist_thresh by 8 when no remaining point passes, but stop reducing once it reaches 32.
  5. Stop at 500 points or when no valid candidates remain.

Review gate: verify the distance rule, the 32 floor, and the threshold backoff match the intended behavior exactly.

Phase 4: 3D HTML plot output

  1. Render the selected points as a Plotly 3D scatter plot.
  2. Wrap the points in a bounding box matching the dataset dimensions.
  3. Include dataset path, seed, threshold schedule, and selected count in the plot metadata.
  4. Write the result to studies/geological_score_selection_study.html as a self-contained HTML artifact for browser viewing and rotation.

Review gate: verify the HTML is portable and the box dimensions match the source dataset.

Phase 5: End-to-end review and testing

  1. Run the study end to end on one discovered dataset.
  2. Verify point count, ordering, and spacing behavior.
  3. Verify the HTML artifact is written to the expected study output path.
  4. Record assumptions and deviations.

Final step: end-to-end code review, testing, and a session summary.
