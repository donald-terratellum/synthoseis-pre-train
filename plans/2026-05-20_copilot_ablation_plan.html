Copilot Ablation Plan

Scope

Concrete run sheet and low-risk implementation plan for seismic reconstruction training on a Mac mini home lab.

Assumptions

  1. 24 GB unified memory on MPS.
  2. 8 active zarr datasets, each approximately 300x300x1500.
  3. Dynamic refresh policy: add 2 datasets and remove 2 datasets each epoch.
  4. Training crops are 128x128x128.
  5. Goal: reduce mean drift and recover label-level variance.
  6. Phase A through C run on current train.py.
  7. Phase D needs small code additions in train.py and models.py.

Common Setup

export DATA_FOLDER=/path/to/your/zarr/root
export RUN_ROOT=checkpoints/ablation_2026_05_20
mkdir -p "$RUN_ROOT"

Recommended Base Knobs

  • batch_size=2
  • grad_accum_steps=16
  • effective batch size 32
  • train_batches_per_epoch=64..80
  • val_batches_per_epoch=24..32
Reason: improves optimization stability without exceeding memory and ensures broad sampling of rotating datasets.

Phase D: Architecture Ablation for Sparse Inputs

Recommendations

  1. Do not switch all residual blocks to strided convolutions.
  2. Use mixed kernel sizes by depth: large shallow, compact deeper.
  3. Keep UNet depth unchanged first, then revisit depth only after loss stabilization.

Required New CLI Flags

  • --block_type
  • --kernel_profile
  • --hidden_dims
Phase D command lines are in the Markdown version and can be run after these flags are implemented.

Plan Improvements for Copilot

  1. Add reproducibility lock.
    • Context: rotating datasets and MPS thermals can create run-to-run variance that obscures true gains.
    • Goal: make A/B comparisons trustworthy for mean/std drift improvements.
    • Implementation:
      • Add --seed and --deterministic in train.py.
      • Seed random, numpy, and torch at startup.
      • Enable deterministic torch mode when requested and log any fallbacks.
      • Use deterministic dataloader seeding via generator plus worker_init_fn.
      • Persist seed/deterministic flags in checkpoint metadata and TensorBoard run metadata.
      • On resume, warn if runtime seed differs from checkpoint seed.
      • Validation gate: repeat A1 with same seed and verify tight tolerance on final val loss and drift metrics.
  2. Add fixed validation holdout support.
    • Context: rotating train datasets can make validation trends non-stationary and hard to compare across runs.
    • Goal: keep a stable validation signal while still benefiting from dynamic train dataset refresh.
    • Implementation:
      • Add --val_paths_fixed and --train_paths_dynamic arguments in train.py.
      • Exclude fixed validation paths from pruning and train-side re-assignment logic.
      • Apply add/drop policy only to the dynamic train pool.
      • Print fixed validation set membership each epoch for traceability.
  3. Add drift metrics logging.
    • Context: primary failure mode is low-frequency mean drift and suppressed output variance.
    • Goal: monitor drift directly so model/loss changes can be judged against the real objective.
    • Implementation:
      • Log global mean and std for prediction and target each epoch.
      • Example:
        • TensorBoard keys: drift/train/pred_mean, drift/train/pred_std, drift/train/target_mean, drift/train/target_std
        • Sample log line: epoch=7 pred_mean=0.031 pred_std=0.62 target_mean=0.002 target_std=0.98
      • Log pooled mean drift at multiple scales (for example kernel sizes 8 and 16).
      • Example:
        • Compute pooled means with avg-pool kernels 8 and 16, then log mean(abs(pool(pred)-pool(target))).
        • TensorBoard keys: drift/val/pooled_mean_drift_k8, drift/val/pooled_mean_drift_k16
      • Log std-ratio std(pred)/std(target) and track convergence toward 1.0.
      • Write these as TensorBoard scalars for train and validation paths.
  4. Add optional low-frequency pooled-mean penalty in losses.
    • Context: local bias fields in large patches are not sufficiently constrained by current objective mix.
    • Goal: penalize low-frequency mean offsets without harming reflector detail.
    • Implementation:
      • Extend losses.py with a pooled-mean L1 term and configurable pool size/weight.
      • Support masked-only computation to align with supervised voxels policy.
      • Add train.py CLI flags to enable and tune this term per run.
      • Log the penalty component separately in TensorBoard for ablation clarity.
  5. Add phase-D architecture flags and print resolved kernel profile.
    • Context: architecture ablations should be reproducible without manual code edits between runs.
    • Goal: enable declarative, scriptable architecture experiments from CLI.
    • Implementation:
      • Add args --block_type, --kernel_profile, and --hidden_dims in train.py.
      • Example:
        • CLI: --block_type anisotropic --kernel_profile mixed_large_shallow --hidden_dims 32 64 128 256
        • Argparse sketch: choices=["resblock","anisotropic"] for --block_type and nargs=4 for --hidden_dims
      • Plumb these through create_model and model factory logic.
      • Implement profile mapping in models.py (for example large-shallow and compact-deep).
      • Example:
        • mixed_large_shallow: stage0/1 kernels (7,5,5), stage2/3 kernels (3,3,3)
        • compact_deep: all stages (3,3,3) with optional anisotropic middle stages
      • Print per-stage resolved kernels/channels at startup and store in checkpoint metadata.
      • Example:
        • Startup print: profile=mixed_large_shallow stage_kernels=[(7,5,5),(7,5,5),(3,3,3),(3,3,3)] hidden_dims=[32,64,128,256]
        • Checkpoint metadata keys: model.block_type, model.kernel_profile, model.stage_kernels, model.hidden_dims
  6. Remove training QC TODO block that recomputes extra losses per batch.

Home Lab Tuning Guidance

  • Keep batch_size=2 on MPS.
  • Use grad_accum_steps=12..16.
  • Start with effective batch 32; reduce to 24 if wall time is too high.
  • Increase train batches 64 → 80 only if swap stays low and thermals are stable.
  • Keep validation batches in 24..32 range.
  • Keep ema_decay=0.995 and polynomial LR schedule.
