Feasibility Assessment: Input-Pipeline-Only Backport

Date: 2026-05-19 | Source branch: feat/unet-decoder-fix | Target baseline: main

Objective: upgrade a new branch from main using only changes related to histogram-equalization and creation of augmented 128x128x128 training inputs, while excluding model architecture and loss-function changes.

Summary Decision

Feasible High Confidence A selective backport is practical and can be performed autonomously with a guarded scope.

Confidence rationale: the desired capability is primarily in data-input modules and train-argument wiring; model/loss changes are separable by file-level exclusion and explicit commit/file filtering.

Branch Comparison Findings

  • Observed branch divergence includes data pipeline, masking/augmentation, train wiring, model architecture, and loss updates.
  • The desired histogram path is centered on src/synthoseis_pre_train/histogram_equalizer.py and associated dataloader/train integration.
  • train_multi_datasets.sh has major flag-surface updates; only its input-pipeline and robustness changes should be ported.
  • Model and loss modifications exist in separate files and can be excluded from port scope.

Key Feasibility Risks and Mitigations

Risk Impact Mitigation
API drift between main and feature branch dataloader/train arguments Runtime arg mismatch or silent defaults Backport with explicit argument map and run smoke invocation using the same CLI profile as current training scripts.
Script-level flag coupling in train_multi_datasets.sh Forwarding unwanted model/loss options or missing required input flags Port by hunk: keep transform/masking flags and diagnostic hardening; drop architecture/loss/SSIM-cluster option additions.
Transform persistence path differences in zarr stores Repeated recomputation or missing metadata Implement/read a stable transform metadata namespace and verify round-trip load/apply behavior.
Unintended model/loss code contamination Behavioral regression outside scope Restrict edits to allowlist files; fail task if staged changes include model/loss files.
Augmentation shape/order assumptions (axis order) Incorrect sample orientation or masking mismatch Add focused tests for shape/order invariants and mask alignment on 128^3 outputs.

Scope for a New Branch from main

Recommended include set:

  • src/synthoseis_pre_train/histogram_equalizer.py (new module)
  • Input pipeline edits in src/synthoseis_pre_train/dataloader.py, src/synthoseis_pre_train/augmentation.py, src/synthoseis_pre_train/masking.py
  • Optional transform helper module if required by branch API: src/synthoseis_pre_train/transforms.py
  • CLI/wiring updates only in train.py
  • Selective script updates in train_multi_datasets.sh for input-transform/masking flags and reliability traps only
  • Targeted tests for histogram mapping and 128^3 sample generation

Recommended exclude set:

  • src/synthoseis_pre_train/models.py, src/synthoseis_pre_train/dyn_models.py
  • src/synthoseis_pre_train/losses.py
